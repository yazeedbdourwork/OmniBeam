같은 Wi‑Fi인데 전송이 느리거나 서버를 거칩니다

같은 Wi‑Fi에서는 OmniBeam이 두 기기를 직접 연결해야 하고, 진행 막대 아래 경로는 "같은 네트워크"여야 합니다. "인터넷", "공유기 경유", "서버를 통해 보내는 중"이라고 나온다면 보통 다음 중 하나가 원인입니다.

1. 연결 점검 실행하기

OmniBeam 아래쪽의 기기 이름 옆에 있는 네트워크 ID를 탭하세요. 이 기기가 로컬 주소를 공유하는지, VPN이 방해하는지, 최근 전송이 어떤 경로였는지 보여 주고, 발견한 문제에 대한 팁도 알려 줍니다.

2. 로컬 연결 허용하기(⚡)

브라우저는 웹사이트에 기기의 로컬 네트워크 주소를 숨깁니다. 그러면 다른 기기는 로컬 이름 조회(mDNS)로 찾아야 하는데, 많은 네트워크가 이를 막아서 전송이 공유기를 거쳐 먼 길로 갑니다. ⚡ 더 빠른 Wi‑Fi 전송을 탭하고 한쪽 또는 두 기기에서 마이크를 한 번 허용하세요. 아무것도 녹음되지 않지만, 브라우저가 로컬 주소를 공유하게 되어 기기들이 직접 연결할 수 있습니다.

3. VPN과 비공개 릴레이 끄기

  • 보내는 동안 두 기기 모두에서 VPN 앱을 끄세요. 백신 프로그램의 "보안 연결" 기능도 포함됩니다.
  • iPhone에서는 iCloud 비공개 릴레이를 끄고, 설정 → Wi‑Fi → 사용 중인 네트워크에서 "IP 주소 추적 제한"을 끄세요.

4. Windows: 개인 네트워크 사용하기

"공용" 네트워크에서는 기기들이 서로를 찾는 데 쓰는 로컬 조회를 Windows가 막습니다. 설정 → 네트워크 및 인터넷 → Wi‑Fi(또는 이더넷) → 사용 중인 네트워크를 열고 개인 네트워크를 고르세요. 방화벽도 개인 네트워크에서 브라우저를 허용해야 합니다.

5. 공유기 확인하기

  • 게스트 네트워크와 "AP 격리" 또는 "클라이언트 격리"는 같은 Wi‑Fi의 기기끼리 통신하지 못하게 합니다. 기본 네트워크를 쓰거나 공유기 설정에서 격리를 끄세요.
  • 일부 공유기는 2.4GHz와 5GHz 네트워크가 따로 있고 서로 격리되어 있습니다. 두 기기를 같은 네트워크에 연결하세요.

그래도 직접 연결되지 않나요?

그래도 전송은 됩니다. OmniBeam이 종단 간 암호화된 채로 서버를 통해 보내며, 조금 느릴 뿐입니다. 코드로 기기를 페어링할 수도 있습니다. 경로가 빨라지지는 않지만 항상 서로를 찾습니다.

같은 Wi‑Fi에서 전송이 느리거나 서버를 거칠 때, 위 단계로 보통 몇 분이면 해결됩니다.

자주 묻는 질문

전송이 서버를 거치는지 어떻게 알 수 있나요?

OmniBeam은 전송에 연결 유형을 표시합니다. 같은 Wi‑Fi의 직접 연결은 보통 초당 수 메가바이트이고, 중계된 연결은 인터넷 업로드 속도에 묶여 훨씬 느린 경우가 많습니다.

게스트 네트워크가 원인이 되나요?

자주 그렇습니다. 게스트 네트워크와 일부 메시 공유기는 안전을 위해 기기들을 분리하므로 전송이 중계를 거치게 됩니다. 직접 연결하려면 두 기기를 기본 네트워크에 연결하세요.

공유기를 재시동하면 도움이 되나요?

가끔은요. 공유기 설정이 괜찮다면 재시동으로 멈춘 상태가 풀릴 수 있지만, 한 기기의 VPN이나 Windows의 공용 네트워크 프로필은 바꾸기 전까지 계속 문제를 일으킵니다.

직접 연결인데도 전송이 느린 이유는?

직접 전송은 경로에서 가장 느린 부분보다 빨라질 수 없습니다. 오래된 휴대폰, 다른 방의 약한 Wi‑Fi 신호, 붐비는 2.4GHz 네트워크 모두 속도를 제한할 수 있습니다. 큰 파일은 공유기 가까이 가거나 5GHz 네트워크를 쓰세요.
